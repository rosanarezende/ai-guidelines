Start from one local command

non-TTY

Automation or redirected output

Prints the textual cockpit. It never attempts interactive prompts in CI or pipes.

direct

Registry command

npm run flow -- work, decide, init, adopt, and update route through the same registry.

The mental model

Flow is not a second rules engine. It is a projection of the governed state already used by cockpit, work, decide, pr-ready, and Human Gate briefing.

1 Snapshot Spec, node, checkpoint, reviews, PR, CI, branch, tree, gate.
2 Derive actions Available, blocked, forbidden, and recommended next action.
3 Briefing What, why, evidence, authority, validation, and consequences.
4 Preview Exact files and effects before anything writes.
5 Confirm Explicit human confirmation for every governed mutation.
6 Apply Narrow write. No hidden gate, Ready, merge, or transition.
7 Next state Work and decide re-read the same state after the effect.

Cockpit when prompts are not appropriate

In non-interactive contexts, the same entrypoint prints a cockpit. It tells the human what is happening and which command is canonical.

State

Active spec, node, checkpoint, PR state, CI, reviews, findings, and tree.

Next action

One recommended action, with the exact command to inspect or execute it.

Boundaries

Available, blocked, and forbidden actions are shown separately.

Readiness is a lifecycle transition

Readiness is not manual editing of tasks.md. It is a governed action with briefing, preview, confirmation, and a narrow effect.

Moment Allowed Blocked Effect
Active sub-checkpoint [/] without readiness Implement, validate, inspect readiness decision. Advance, Human Gate, Ready, merge. No write.
Criteria satisfied Declare readiness through decide. Starting the next sub-checkpoint automatically. Only tasks.md receives readiness: ready-for-transition.
After readiness Inspect or decide advance-subcheckpoint. Human Gate until all sub-checkpoints close and PR policy passes. No hidden transition.

Provisioning stays available

init, adopt, and update remain first-class. Provider selection happens inside those operations.

init

New repository

Creates the governed baseline for an empty target, with provider and feature selection.

adopt

Existing repository

Conservative adoption that preserves existing project files and managed blocks.

update

Re-apply baseline

Updates templates/runtime and accepts --providers claude,openai.

No providers command. The old providers verb does not exist in the new runtime. Use npm run flow -- update --providers claude,openai.

Safety rules are visible

The flow is designed to make unsafe actions obvious before the human can choose them.

Available

Executable now

Shown with command, authority, and expected effect.

Blocked

Not yet executable

Shown with factual blockers such as CI pending, Draft PR, stale review, or dirty tree.

Forbidden

Not authorized here

Ready, Human Gate, merge, gate artifact, and node transition stay out unless the governed state allows them.
