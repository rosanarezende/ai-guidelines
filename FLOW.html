Uma entrada local, dois comportamentos seguros

O mesmo comando se adapta ao contexto. Ele é interativo quando existe pessoa no terminal e determinístico quando está rodando em CI, pipe ou execução não interativa.

TTY

Terminal interativo

Abre o wizard Clack com menu, escolhas humanas, prévias e confirmações.

non-TTY

Automação ou saída redirecionada

Renderiza o cockpit textual. Não tenta prompt interativo em automação.

comando direto

Registry ativo

work, decide, init, adopt e update continuam roteados pelo registry.

O modelo mental

O wizard não é uma segunda fonte de regra. Ele projeta a mesma derivação usada por cockpit, work, decide, pr-ready e briefing de Human Gate.

1 Snapshot Spec, nó, checkpoint, reviews, PR, CI, branch, tree e gate.
2 Ações derivadas Disponíveis, bloqueadas, proibidas e próxima recomendada.
3 Briefing O que, por que, autoridade, evidência, validação e consequência.
4 Prévia Arquivos e efeitos exatos antes de qualquer escrita.
5 Confirmação Decisão humana explícita para cada mutação governada.
6 Aplicação Escrita estreita. Sem Ready, Gate, merge ou transição escondida.
7 Próximo estado O runtime relê o estado; não depende de memória do agente.

    Cockpit quando prompt não é apropriado

    Em non-TTY, o comando imprime o cockpit. Ele mostra o que está acontecendo e qual comando canônico inspeciona ou executa a próxima ação.

    Estado

    Spec ativa, nó, checkpoint, PR, CI, reviews, findings e árvore Git.

    Próxima ação

    Uma recomendação principal, com comando exato para inspeção ou decisão.

    Fronteiras

    Ações disponíveis, bloqueadas e proibidas ficam separadas por motivo.

    Conclusão de sub-checkpoint é uma decisão única

    No caso comum, a pessoa não precisa aprovar readiness e depois aprovar advance. O fluxo valida os critérios de saída e oferece uma única decisão governada.

    Momento Permitido Bloqueado Efeito
    Sub-checkpoint ativo [/] sem readiness Implementar, validar e inspecionar o próximo ato. Avanço, Human Gate, Ready e merge. Nenhuma escrita.
    Critérios satisfeitos e há próximo [ ] Decidir finish-subcheckpoint. Implementar o próximo sub-checkpoint automaticamente. Somente tasks.md: atual [/] → [x] e próximo [ ] → [/].
    Último sub-checkpoint Usar readiness terminal e preparar fechamento do checkpoint. advance-subcheckpoint indevido. Human Gate continua separado e exige Ready/CI/política.

    Provisioning continua disponível

    init, adopt e update seguem como comandos de primeira classe. A seleção de providers acontece dentro dessas operações.

    init

    Repositório novo

    Cria o baseline governado em target vazio, com providers e features selecionáveis.

    adopt

    Repositório existente

    Adoção conservadora que preserva arquivos existentes e blocos gerenciados.

    update

    Reaplicar baseline

    Atualiza templates/runtime e aceita --providers claude,openai.

    Não existe comando providers. Use npm run flow -- update --providers claude,openai. Isso é substituição canônica, não alias.

    Regras de segurança ficam visíveis

    O fluxo mostra por que algo pode, não pode ou ainda não pode acontecer. Essa distinção evita decisões acidentais.

    Disponível

    Executável agora

    Aparece com comando, autoridade necessária e efeito esperado.

    Bloqueada

    Ainda não executável

    Nomeia bloqueios factuais: CI pendente, PR Draft, review stale ou tree suja.

    Proibida

    Fora da autorização

    Ready, Human Gate, merge, gate artifact e transição de nó só entram quando o estado permite.

    Mapa de comandos

    Use estes comandos quando quiser o caminho direto em vez do wizard.

    Necessidade Comando
    Abrir wizard ou cockpit textual npm run flow
    Forçar cockpit textual npm run flow -- cockpit
    Retomar sessão de spec npm run flow -- handoff 0024
    Carregar contrato de implementação npm run flow -- work --authorization explicit-work-request
    Inspecionar decisões humanas npm run flow -- decide --brief-only
    Provisionar repositório npm run flow -- init, adopt ou update
    Regra canônica: esta página explica a experiência. A verdade executável continua sendo o estado versionado do repositório, o registry de comandos e a derivação governada usada pelo runtime.
