# q3 — expor erros de validação: estado controlado ou render-prop/slot?

**Pergunta:** como o componente ENTREGA os erros pro consumidor renderizar?

## Opções (modo `escolha`) — SEM enviesar

### Opção A — estado controlado (componente expõe `errors` + renderiza a msg padrão)

- **Problema que resolve:** erro consistente no DS, zero-config.
- **Benefícios:** padrão único · fácil de usar.
- **Tradeoffs:** amarra o visual do erro.
- **Riscos:** consumidor com design próprio fica limitado.
- **Quando escolher:** consistência do DS é prioridade.
- **Quando NÃO escolher:** MFEs precisam de erro muito custom.

### Opção B — render-prop/slot (consumidor recebe o erro e renderiza)

- **Problema que resolve:** flexibilidade visual por MFE.
- **Benefícios:** cada um renderiza como quiser.
- **Tradeoffs:** cada um pode divergir do padrão do DS.
- **Riscos:** inconsistência visual entre MFEs.
- **Quando escolher:** designs muito diferentes entre consumidores.
- **Quando NÃO escolher:** quer padronização forte.
