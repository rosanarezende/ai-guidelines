# res-001 — como libs de form do mercado expõem validação

> Data: 2026-06-28

**Questão(ões):** q1 (schema declarativo × regra imperativa).

**Evidência / achados:**

- Bibliotecas maduras convergem em **schema declarativo** como default (regras nomeadas:
  required/email/min/pattern) **+ um escape hatch** pra regra custom (uma função `validate`).
- O schema **serializa** (dá pra documentar, testar e versionar a regra); a função custom
  cobre o que o schema não prevê, sem virar a API principal.
- Quem expõe **só** a função imperativa empurra a regra comum pra cada consumidor →
  reimplementação (exatamente o que o `form-component` quer evitar).

**Recomendação (escolha, bounded):** Opção A (schema declarativo) **com** escape hatch
imperativo — o humano decide e pode divergir.
