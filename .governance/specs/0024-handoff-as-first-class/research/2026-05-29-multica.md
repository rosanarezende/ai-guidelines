## O que o Multica modela

| Mandato                      | Achado                                                                                                                                                                    |
| :--------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Object vs transformation** | **Object-centric.** "The spine is **Agent + Task**, not a transformation pipeline." Objetos de 1ª classe: Agent, Task/Issue, Skill, Squad, Runtime, Workspace, Autopilot. |
| **Fronteira humano→sistema** | **Fina e unidirecional.** Humano decide _assignment_; sistema executa autônomo. "No human approval gate between assignment and execution."                                |
| **O que atravessa**          | Uma **delegação de tarefa** ("assign issues to an agent like a colleague"), **não** julgamento cristalizado em governança.                                                |
| **Cristalização**            | Parcial — skills/autopilots/configs persistem; task state/logs efêmeros. Versionamento não detalhado.                                                                     |
| **Gate humano governado**    | **Não** (autônomo pós-assignment).                                                                                                                                        |
| **Primitivo vs derivado**    | Primitivos: Agent, Runtime, Task, Workspace. Derivados: Skill, Squad.                                                                                                     |
| **Para quê serve**           | Transforma _human task-assignment + agent capability_ → _autonomous work completion + reusable knowledge_.                                                                |

## Bearing no G00 — BOUNDA a hipótese (resultado forte)

A hipótese pivotada era: _"o fundamental é uma **transformação governada de contexto humano → governança executável**, com fronteira humano→sistema espessa"_. Multica **testa e delimita**:

- Multica é **object-centric (Agent+Task), NÃO transformation-centric.** → **A transformação NÃO é universal.**
- Sua fronteira humano→sistema é **FINA**: o humano delega e sai; o sistema roda autônomo. O que cruza é uma **delegação**, não julgamento-virando-governança.
- **Sem gate governado**; cristaliza **skills** (estilo autônomo, como Hermes), não governança.

→ Multica cai na **classe autônoma** (perto do Hermes), não na governance-first. Isso **não refuta** a hipótese para o ai-guidelines — **delimita** seu escopo.

## Síntese cruzada (4 sistemas, mandato pivotado)

| Sistema           | Classe              | Spinha                                  | Fronteira humano→sistema              | O que atravessa            |
| :---------------- | :------------------ | :-------------------------------------- | :------------------------------------ | :------------------------- |
| **Spec Kitty**    | spec-driven         | lifecycle (transformação) + Mission     | **espessa** — review/accept/merge     | decisão humana (accept)    |
| **ai-guidelines** | governance-first    | **transformação** (contexto→governança) | **espessa** — gate / decision session | julgamento cristalizado    |
| **Hermes**        | autonomous-learning | loop + multi-entidade                   | **fina** — skill auto-creation        | mínimo (auto-gerado)       |
| **Multica**       | agent-orchestration | **Agent+Task (objetos)**                | **fina** — assign → autônomo          | delegação (não julgamento) |

### A correlação estrutural (a descoberta)

> **Transformation-centric + fronteira humano→sistema ESPESSA** ⟺ **governance-first** (ai-guidelines, Spec Kitty).
> **Object-centric + fronteira FINA/autônoma** ⟺ **autonomia** (Hermes, Multica).

A **espessura da fronteira humano→sistema** é o eixo que separa as classes. Sistemas autônomos **afinam** a fronteira (delegam e saem); governance-first a **engrossa** até virar o core.

**O que isso diz de G00 (forte, grounded + 4 sistemas):**

- O fundamental do ai-guidelines **não é um objeto** (regresso infinito refutado) **nem uma transformação universal** (Multica/Hermes refutam universalidade).
- É a **transformação governada de `contexto humano → governança executável` com fronteira espessa** — a **assinatura da classe governance-first**, e a **identidade arquitetural** do framework. Isso é **exatamente** o que ADR 0018 crava (AI-as-channel; sem LLM no runtime; o julgamento humano cruza, o runtime só aplica). O que Hermes/Multica minimizam por autonomia, o ai-guidelines maximiza por governança.

**Não-coroação:** "transformação" não venceu como verdade universal — venceu como **assinatura de classe**, delimitada por contraste. Isso é resultado da disciplina de falsificação funcionando: a hipótese sobreviveu **bounded**, não absoluta.

## Limitações

- Docs do Multica são finos (sem detalhe de versionamento/skill storage; sem gate documentado — pode ser lacuna de doc, não de design).
- Faltam **Cursor** e **Open Code** (harness systems, governance-leve) para fechar: eles **engrossam** ou **afinam** a fronteira? Se um harness governance-leve ainda engrossar, fortalece "espessura ⟺ governança"; se afinar, idem.
- 2 governance-first (espessa) × 2 autônomos (fina) = contraste limpo, mas n pequeno.
